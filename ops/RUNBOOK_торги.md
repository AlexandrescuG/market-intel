# Торги стоят. Что делать без Клода

Написано 29.09.2026 после простоя в одиннадцать дней (18–29.09). Рассчитано
на то, что читать его будет владелец, а меня рядом не будет — например,
потому что подписка не оплачена.

Все команды выполняются как есть, из любого каталога. Ничего знать заранее
не нужно.

---

## 0. Один вопрос вместо разбирательства

```bash
cd /mnt/sbfdata/sbf-platform/market_intel && .venv/bin/python ops/pulse.py --молча
```

Ответ — один из трёх:

| Вердикт | Что значит | Насколько срочно |
|---|---|---|
| 🟢 Торги идут | путь до ордера работает | ничего не надо |
| 🟡 Торги идут, но урезаны | ордера идут, часть источников отвалилась | не срочно, §2а |
| 🔴 ТОРГИ НЕ ИДУТ | до ордера дело не доходит | по причине ниже |

Под вердиктом идут причины строками. Заголовки в этом файле повторяют
формулировки пульса дословно — ищите свою.

Отдельно: **зелёный не означает «торгует хорошо»**. Пульс отвечает только на
вопрос «доходит ли дело до ордера». Прибыльность — не его дело.

Этот же пульс сам пишет в Телеграм — но **только когда вердикт меняется**,
плюс один раз в сутки. Если сутки не приходило ничего вообще, это само
по себе неисправность: смотрите §5.

## 1. «мост … не поднимается (порт … молчит)»

Мост — это MetaTrader под Wine плюс rpyc-сервер к нему. Без него ордера
физически некуда отправлять.

```bash
export XDG_RUNTIME_DIR=/run/user/$(id -u)
systemctl --user restart sbf-mt5-bridge.service        # демо Ava, порт 18812
systemctl --user restart sbf-mt5-bridge-real.service   # реал Daoti, порт 18813
sleep 30 && ss -ltn | grep 1881
```

Должны быть обе строки — `127.0.0.1:18812` и `127.0.0.1:18813`. Пульс делает
этот рестарт сам, поэтому если сообщение пришло — значит автоматический
рестарт не помог, и дело в терминале.

**Терминал висит и не принимает клики** — известная болячка (16.09). Лечится
только убийством и подъёмом заново:

```bash
pkill -f terminal64.exe
export XDG_RUNTIME_DIR=/run/user/$(id -u)
systemctl --user restart sbf-mt5-bridge.service sbf-mt5-bridge-real.service
```

**Терминал просит логин.** Пароли ввожу не я, а вы — руками, в окне
терминала. После входа мост поднимется сам в течение 30 секунд.

## 2. «входы приостановлены предохранителем»

Это защита: в дереве лежат незакоммиченные исходники движка, то есть
чей-то недописанный код, а движок запускается прямо из дерева.

Сначала посмотрите, что именно:

```bash
cd /mnt/sbfdata/sbf-platform/market_intel && git status --porcelain -- analyze/engine
```

С 29.09 предохранитель снимается сам, если правки не трогали два часа **и**
тесты движка зелёные. Если он всё равно держит — значит одно из двух условий
не выполнено, и в сообщении пульса написано какое.

Тесты красные — трогать движок нельзя, ждите меня. Это тот случай, когда
простой дешевле торговли сломанным кодом.

Если правки не нужны (например, это мой брошенный черновик):

```bash
cd /mnt/sbfdata/sbf-platform/market_intel && git checkout -- analyze/engine
```

## 2а. 🟡 «Торги идут, но урезаны» — `alpha_forecast` молчит

Это **не остановка**. Ордера идут, но один источник сигналов из одиннадцати
выключился. Именно этот случай наступает, когда не оплачен Клод.

Как устроено: источник `alpha_forecast` читает таблицу `forecasts`, а её
наполняет `agent_run` через `claude` CLI. Окно свежести — три часа. Нет
агента → нет свежих прогнозов → источник молчит, и снаружи это выглядит как
«сигналов стало меньше».

Замерено 29.09.2026: это 20.3% сделок демо и 9.3% реала, вклад **+0.59 R на
46 сделках**, то есть практически ноль. **Торговать без него можно.**

Проверить, он ли:

```bash
cd /mnt/sbfdata/sbf-platform/market_intel && .venv/bin/python -c "
import sys,time; sys.path.insert(0,'.')
from analyze.engine import ledger
r=ledger.connect().execute('SELECT max(created_ts) FROM forecasts').fetchone()
print(f'последний прогноз {(time.time()-r[0])/3600:.1f} ч назад (окно 3 ч)')"
```

Что делать: ничего срочного. Оплатить/восстановить доступ, когда удобно —
остальные десять источников работают. Ждать меня для этого не нужно.

**Чего делать НЕ надо:** останавливать движок из-за жёлтого. Жёлтый — это
про урезанный поток сигналов, а не про неисправность исполнения.

## 2б. «КОТИРОВКИ МЁРТВЫЕ — последний тик N ч назад»

**Это сторона брокера, и ни я, ни перезапуск тут не помогут.** Проверено
07.10: терминал перезапущен начисто, залогинен, `connected=True` — и всё
равно ни одного нового тика.

Что происходит: брокер перестал присылать цены. Терминал при этом выглядит
здоровым, а любой запрос — перенос стопа, закрытие, новый вход — отбивается
с `retcode=10006 Request rejected`, потому что построен на старых ценах.

🔴 **Самое важное: equity и «плавающая прибыль» в терминале в этом состоянии
посчитаны по мёртвым ценам и НЕПРАВДИВЫ.** 07.10 терминал реала показывал
+38.60, а по живым ценам те же позиции стоили совсем другое. По этому числу
нельзя судить ни о результате, ни о просадке.

Что делать:

1. Убедиться, что дело в брокере, а не в нас — сравнить с демо:

```bash
cd /mnt/sbfdata/sbf-platform/market_intel && .venv/bin/python -c "
import sys,time; sys.path.insert(0,'.')
from analyze.mt5_calibration import Bridge
from analyze.engine.accounts import ACCOUNTS
for n,s in (('demo','EURUSD'),('real','EURUSD.')):
    a=ACCOUNTS[n]
    with Bridge(port=a.port, lock=a.lock) as (m,c):
        t=m.symbol_info_tick(s)
        print(n, s, t.bid, f'возраст {(time.time()-t.time)/3600:.1f} ч')"
```

Если демо свежее, а реал нет — это счёт, а не машина.

2. **Написать партнёру/брокеру.** Тестовый счёт мог истечь, быть переведён в
   режим только чтения или отключён. Это единственный путь.
3. Открыть счёт в веб-терминале брокера и посмотреть настоящее состояние:
   позиции могли давно закрыться по цели, а наш терминал показывает снимок
   недельной давности.

Движок при этом трогать не нужно: он честно пытается работать и честно
получает отказ. Демо-счёт продолжает торговать как обычно.

## 3. «таймер движка не enabled»

```bash
export XDG_RUNTIME_DIR=/run/user/$(id -u)
systemctl --user enable --now sbf-engine.timer sbf-engine@real.timer
```

⚠️ Обратное — **выключать торговлю через `systemctl disable` бесполезно**:
следующий прогон `~/sbf-start-all.sh` включит обратно, потому что источник
правды — `ops/units.txt`. Чтобы выключить по-настоящему, поменяйте роль
юнита на `off` в этом файле.

## 4. «нет новых сделок N сут», но всё остальное зелёное

Само по себе это **не отказ**. Движок штатно молчит, когда нет сигналов или
когда риск портфеля уже выбран. Порог в трёх сутках выбран так, чтобы не
дёргать зря.

Проверить, доходит ли дело до решений:

```bash
cd /mnt/sbfdata/sbf-platform/market_intel && .venv/bin/python -m analyze.engine.run --dry-run --account demo 2>&1 | tail -20
```

В выводе должны быть строки `-> принят` и `dry-run: объём ...`. Если объём
везде `0.00` — сигналы есть, но размер не проходит: скорее всего выбран риск
портфеля или счёт слишком мал для минимального лота. Это нормальная работа
ограничителя, а не поломка.

Если строк `принят` нет вовсе — молчат источники, и это уже ко мне.

## 5. Сутки не было ни одного сообщения от пульса

Значит не работает сам надзор. Проверьте по порядку:

```bash
export XDG_RUNTIME_DIR=/run/user/$(id -u)
systemctl --user list-timers 'sbf-*' --no-pager | head -20
systemctl --user --failed --no-pager
journalctl --user -u sbf-pulse -n 30 --no-pager
```

Если очередь сообщений встала (пульс пишет в неё, а отправщик молчит),
проверьте бота:

```bash
export XDG_RUNTIME_DIR=/run/user/$(id -u)
systemctl --user status sbf-academy-bot --no-pager | head -15
```

## 6. Полная остановка торговли (если сомневаетесь — делайте это)

Стоять безопаснее, чем торговать непонятно чем. Открытые позиции при этом
**продолжают сопровождаться** — сведение и переносы стопа не останавливаются.

```bash
export XDG_RUNTIME_DIR=/run/user/$(id -u)
systemctl --user stop sbf-engine.timer sbf-engine@real.timer
```

И поменяйте роль этих двух юнитов на `off` в `ops/units.txt`, иначе
`~/sbf-start-all.sh` их вернёт.

Закрыть всё руками — в самом терминале MetaTrader, правой кнопкой по
позиции. Я этого делать не могу и не буду: закрытие позиций деньгами — не
моё решение.

## 7. Чего в этом runbook нет сознательно

- **Пароли и логины.** Я их не ввожу — ни на демо, ни на реальном счёте.
  Всё, что требует авторизации, делаете вы руками в окне терминала.
- **Решения о деньгах.** Довнести, вывести, закрыть просадку — не здесь.
- **«Почему стратегия стала терять».** Это разбор, а не восстановление;
  восстановление — вернуть путь до ордера, и только.

вердикта на зелёный. Прежний механизм на том же промежутке отправил бы десять.

### Что важно знать про сам движок

Торговый движок **от Клода не зависит**: в `analyze/engine` нет ни одной
ссылки на агента. Сигналы, риск, ордера, сопровождение позиций и стоп-краны
работают без меня сколько угодно долго. Неоплата Клода отключает аналитику
(прогнозы, брифинги, тексты), но не торговлю — максимум урезает поток
сигналов на одну девятую, и об этом теперь сообщает жёлтый вердикт.
